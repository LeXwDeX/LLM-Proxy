# internal/proxy — 代理转发层开发约束

> 本目录是核心转发逻辑所在，改动最频繁、故障影响最大。改动前先读本文件；项目级约束见根目录 `AGENTS.md`。仓库当前不维护 `docs/architecture.md`。

## 模块地图（改哪个文件先看职责）

| 文件 | 职责 |
|---|---|
| `service.go` | 请求编排中枢：鉴权后路由、目标选择、失败静默、指标 |
| `forward.go` | HTTP 转发执行：上游请求构造、调用 provider 认证策略、流式回写 |
| `provider_profile.go` | 由 config 元数据派生 Provider Profile，将认证、路径与 query 策略绑定到目标 |
| `url.go` | 上游 URL 拼装；`isAnthropicStylePath` 等路径形态判断 |
| `protocol.go` | 共享请求 schema 分类 → 协议类型解析（`ResolveProtocol`），保留旧 helper 默认值 |
| `path_capability.go` | 共享请求 schema 分类，消费 config 的能力声明（目标选择时过滤不兼容 target） |
| `affinity.go` | 连接粘连：同客户端+同模型 TTL 5 分钟；会话级粘连按客户端+会话+客户端模型名（小写）保持同一 target，滑动 TTL 24 小时，优先识别 `X-Session-Affinity`、`X-Session-Id`、`session_id`、`X-Claude-Code-Session-Id`，均惰性过期。IP 亲和 Set 侧写实际服务成员的上游原始拼写，Get 侧依次尝试该请求名在各成员映射出的上游拼写 |
| `binding_write.go` | IP/会话绑定写入（`writeBindings`）与结算（`settlePrewrittenBindings`）：2xx 头提交前预写，未完整送达则 compare-and-restore 回滚；见红线 1 下的“粘连写入” |
| `keypool.go` | 多 API Key 池状态机：客户端亲和、耗尽检测、冷却恢复 |
| `keypool_probe.go` | 耗尽 key 的恢复探测，使用 provider 的认证与探测路径策略 |
| `responses_ws.go` | HTTP `/v1/responses` 经上游 WebSocket 连接池转发（target `prefer_websocket`，仅 openai）；握手前可回退 HTTP，发送后不重放 |
| `responses_websocket.go` | 原生下游 WebSocket 会话（`GET /v1/responses` 升级）：逐轮鉴权与准入、上游 WS/HTTP 回退、空闲超时与关闭排空 |
| `glm_ratelimit.go` | 智谱 GLM 5 小时限流识别（HTTP 200 + SSE 内嵌 error，非标准 429） |

| `models.go` / `test_model.go` | 模型名提取与校验 / 本地 `/v1/models` 拦截 |
| `multipart_convert.go` | multipart/form-data → JSON 自动转换 |
| `usage.go` | 用量采集（OpenAI / Claude / Gemini 三种响应格式） |
| `response_observation.go` | HTTP 响应观察副本的 identity/gzip/deflate/zstd/br 解码；用量与 trace 共用，保持原始转发字节 |
| `custom_inject.go` | 目标级自定义 Header/Body 注入 |
| `pool.go` | 部署池：池成员调度与 `X-Proxy-Pool` 头来源 |
| `cost_routing.go` | 部署池成本优先（`routing_strategy` 空值或 `cost`；`config.EffectiveRoutingStrategy()` 空值为 `cost`，显式 `load` 为性能优先、不分层；默认成本优先，不做数据迁移，存量显式 `load` 的池不变）的成本分层：以客户端请求的模型名（别名）为比较单位，成员须经自身 `model_mappings` 解析该名（命中 upstream 或逗号分隔 fallback，paused 映射除外；无映射成员按请求名本身）后，按 `(target, 自身上游名, 选路时刻)` 调 `pricing.Resolver.RateFor`（固定参考 token 组合）估算，成本相差 5% 内为同层；上游名请求不反查别名，不以别名声明价回退；价格源不可用时退回负载均衡；否则按层从便宜到贵逐层选择（A=B < C=D < E：AB 同层负载均衡并互为灾备，整层不可用——冷却/已尝试/硬容量满——或饱和（软上限）时才溢出到 CD，再到 E；全层饱和才在已准入候选间负载均衡）。成本分层不主动打断粘连，只决定无粘连请求或粘连目标无法承接时的改选。Debug 级 `cost routing candidates` 输出 alias-first 候选、上游名与价格分组 |
| `cost_routing_preview.go` | 成本预览快照（只读）：按客户端请求名复用 `cost_routing.go` 的 `rateSource`、`RateFor(target, 成员上游名, now)`、5% 同层容差与固定参考 token 组合，输出 `resolved_via`（alias/upstream/unrestricted/none）、`eligible`/`priced`/`estimated_cost_usd`/`tier`/`reason` 及 `phase`/`in_flight`/`max_concurrency`/`affinity_soft_cap_reached`；存在可参与且有价成员时，`members` 按 eligible+priced（tier 0→1，层内估算成本升序）→ eligible unpriced → ineligible 排序，同组按 target 名排序；不获取探针、不读/改粘连、不改变选路，不套模型组 `cost_coefficient`、不含条件价与实际 token。定价源未配置/解析器为空时 `pricing_available=false` 并保留静态 `pricing_error`；解析器报错时同样不可用，但 `pricing_error` 统一为 `pricing source unavailable`，原始错误只写服务端日志；成员仍返回，可解析成员标 `pricing_unavailable`。守护用例：`TestCostRoutingPreviewRanksAliasMembers`、`TestCostRoutingPreviewToleranceBoundary`、`TestCostRoutingPreviewEligibilityReasons`、`TestCostRoutingPreviewPricingUnavailable`、`TestCostRoutingPreviewDoesNotTouchRuntimeState` |
| `model_rewrite.go` / `request_path.go` | 请求体/URL 模型名改写（大小写保留契约）与请求路径识别（`unknown_request_path`、`invalid_responses_path` 等错误码实现处） |
| `json_members.go` | 唯一的顶层 JSON 成员扫描器（all/last/lastFold 查询与受保护成员规范化），HTTP 与 WS 共用 |
| `no_official_usage.go` | 未取得官方最终用量时的统一结算（`settleNoOfficialUsage`）：0 token 事件、诊断、Warn 日志与计数，各协议/传输共用 |
| `wire_transport_test.go` / `responses_ws_prewarm_test.go` | 连接层参数（TLS 会话缓存、h2、拨号超时）与 WS 预热的守护用例 |
| `usage_protocol_*.go` / `usage_patch_*.go` / `usage_adapter*.go` / `usage_context.go` / `usage_stream.go` | 各协议用量解析、流式累计合并与用量上下文适配族 |
| `provider_error_*.go` | 各 provider 错误响应的归一化识别（ breaker / keypool 依据） |

## 🚨 红线约束（有回归测试守护，禁止破坏）

1. **重试与 failover**：
   - WS 与 HTTP 只是不同传输：重试、failover、key 冷却、熔断与 AIMD 判据共用同一套规则；任何只适用于某一传输的例外须写在本节并有回归守护，不得在传输层另起一套判据。
   - 预提交的上游 4xx（除 408）出队到下一候选：仅当 `allowFallback=true`、尚未向客户端写出任何字节、且错误响应可完整缓存（至多 64 KiB）时，按当前选路策略重新选择下一个候选（成本池按成本排序）。判据唯一入口为 `failover.go` 的 `classifyNon2xxAttempt`。显式 `X-Proxy-Target` 时 `allowFallback=false`，不出队，只允许同 target 切 key。
   - 账户级拒绝（`accountRejectionDetail`）：上游 401/402/403 视为代理自身账户在该目标被拒（客户端鉴权已在本地完成）。已确认：非审核类 403 带结构化 code/type/status（`structuredRejection`）、可读体的账户级 402（`targetKeyExhausted`；OpenRouter in-flight/weight 402 不算拒绝）、命中既有凭据规则的 401；未确认：其余非审核 403、所有其他代理凭据 401、不可读体的 402。两类都出队。目标冷却经 `Service.applyAccountRejection` → `targetState.markAccountRejection` 原子完成：已确认取 401/402/403 类（`upstreamForbiddenCooldown`，可配），未确认首次取 `unverifiedRejectionCooldown`（`401_unverified`/`403_unverified`，默认 5 分钟），上次未确认冷却结束后 `unverifiedEscalationWindow`（1 小时）内再现且无成功才取固定冷却；目标已处于账户冷却时的结果视为同一事故迟到，只计数、不升级、不重计 `countRejectionMute`。多 key 目标先由 `markKeyAccountRejection` 给 key 记 `forbidden`（已确认，固定冷却）/`forbidden_unverified`、`unauthorized`（短冷却）或既有分类原因并换 key；4 KiB 预读不能完整解码（截断、gzip 失败、未知编码）的 403 不在预读处封 key，交由出队阶段按 64 KiB 完整体判定是否审核。其中体不超过 64 KiB 且可完整读取、解码的，key 循环在退出前由 `classifyDeferredKeyRejection` 按完整体补做分类（非审核类按已确认/未确认封该 key 并轮换下一个 key，审核类不封不轮换），再进入结算；超过 64 KiB、读取出错、未知编码保持原语义（留给出队阶段）。守护用例：`review_pr201_test.go`。key 循环收敛时若 `targetHasServingKeys` 为假，按 `keyReasonConfirmed(reason)` 立即冷却目标；若仍有可用或仅短暂限流的 key，只出队本请求、目标按 `markReachable` 结算。客户端凭据（`attemptUsesClientCredential`：bearer 透传）下的 401/402/403 不封 key（含 `targetKeyExhausted` 与原生 WS `observeResponsesKeyFailure`）、不冷却目标、不出队，原样透传；出队块判定为审核类或客户端凭据而跳过时清除 `accountLevelFailure`，收敛结果不再冷却目标。审核类 403（`upstreamContentModeration`：结构化 code/type 为 `content_filter`/`content_policy_violation`/`moderation_blocked`，或显式选择 OpenRouter Patch 时的 `metadata.reasons`/`flagged_input`；为合同假设，不按 host/模型名/文本推断）透传、不冷却。单 key 429 直接出队，目标按 429 类分类冷却；多 key 429 仍须先走 keypool 的分类、同 key 重试、换 key 与安全阀，全 key 耗尽后才按既有 `retryable` 升级出队。全部候选均因账户拒绝冷却（`blockage.accountOnly`：无普通冷却、满载或恢复中的兄弟候选）时，选路失败返回原状态码（401 经 `clientFacingStatus` 为 503）与代理生成的 `upstream_rejected` 错误体（`writeUpstreamRejectionCooldown`，带 `Retry-After`，不回放上游正文）；其余全冷却仍为 503。计数 `requests.upstream_rejection_muted_total`/`upstream_rejection_muted_by_status`。守护用例：`failover_rejection_test.go`、`failover_403_test.go`、`failover_review_test.go`、`TestClassifyNon2xxAttempt` 及 e2e `failover_rejection_test.go`。5xx/408、已提交响应（SSE 已写头/Flush、WS 101、Responses 已转发 event）、已发送超时/断流、客户端取消与本地 quota/admission/accounting/参数错误仍终止，不重放；5xx/408 可能已被上游计算或计费，禁止出队。普通 503 的守护测试为 `TestService503PassThroughNoRetry`。
   - 4xx 出队在丢弃点结算健康：账户拒绝走上条规则，单 key 429 记 429 类失败，其他 4xx 按 `markReachable(now, lease != nil)` 记可达（未在冷却时等同 `MarkSuccess` 并释放 probe；冷却中只有持有探针的请求能结束普通冷却，账户冷却只由成功响应清除），不写用量；成功候选拥有唯一 usage bundle，`Event.Model` 仍是该候选的 upstream 名（不是 alias）。队列耗尽时回放第一个真实 4xx（status、原始 headers、body 与 `X-Proxy-Target`/`X-Upstream-Request-Id` 成对；代理 key 的 401 按 `clientFacingStatus` 显示为 503），没有真实响应时才合成 502/503/504。**成文例外（粘连终态仲裁，见下）**：被其粘连目标持有的请求不回放替代目标的 4xx，改返回 503 + `Retry-After`；粘连目标自己的 4xx（含 429）整体替换已缓存的替代应答。`/admin/metrics` 的 `requests` 增加 `dequeued_total`、`dequeue_exhausted_total`、`cached_error_replayed_total`、`dequeue_4xx_total`；每次 4xx 出队计入 `target_retries`（保持 `retries`=`key_retries`+`target_retries`），4xx 出队不增加 `failures`，最终客户端结果只计一次。
   - 密钥池有有限例外：HTTP 429 和 GLM 瞬时限流可有限重试同一 key，达到限制后换 key；只有通用 `rate_limited` 与 GLM 瞬时类（1302/1303/1305）可坚持同 key；识别出的 GLM 额度类、余额/额度耗尽（如 `credit_balance_exhausted`）与 GLM 账户级失效（1113 欠费、1309 套餐到期，永久屏蔽，管理端唤醒直接恢复）跳过同 key 重试，进入换 key 路径（`sameKeyRetryable429Reason`）。符合条件时，全 key 耗尽可进入 target failover。同 key 重试次数**按请求内的本地计数**限定（`sameKeyRetries`：本次尝试里每个 key 至多同 key 重试一次），不依赖按 key 共享的 `consecutiveFails`——它会被同 key 上任何模型的成功清零，不能单独作为界（`TestMultiKeySameKeyRetryIsBoundedPerRequest`）；全局四次上限不变。具体条件与次数以 `service.go`、`forward.go`、`keypool.go` 及其用例为准，不得扩展为任意错误重试。上游 WS 池的握手拒绝（未发送生成事件、非代理本地应答）按同一规则处理；已发送生成事件的 WS 响应永不进入 key 重试。
   - 原生下游 WS 在**当前轮生成发送前**的握手拒绝与 HTTP 共用同一套判据，并进入同一 key 循环与跨 target 出队：完整且不超过 64 KiB 的错误体使用共享分类器；401/403 与 HTTP 相同经 `markKeyAccountRejection` 记 key 冷却（已确认/未确认）并换 key，402 按既有状态规则换 key，429 保留每 key 两次、全局四次换 key 的有限策略，额度类跳过同 key（`observeResponsesKeyFailure`，空体亦同，客户端凭据豁免）；同原因收敛或 key 用尽后与单 key 目标一样进入跨 target 出队：账户拒绝按上文规则冷却目标，在允许 failover（非显式目标）时同一轮切到下一个候选，候选耗尽回放首个真实拒绝为原生错误事件（保留上游 `error` 对象，代理 key 的 401 事件状态为 503）；超长/读取失败/取消的部分错误体与显式 `X-Proxy-Target` 保持终止、不熔断。原生拒绝出队时通过 `responsesWebsocketRejectionBody.settleWith` 以同一 once 完成该次握手健康结算（不得再由 `Close` 以普通结果覆盖固定冷却），原始体关闭一次、保存的拒绝响应关闭时释放 key/节点占用，出队不进入 `writeResponse`，最终客户端指标只结算一次。已发送 `response.create` 之后的终态 403 绝不重放、不跨 target、不熔断目标，仅可让该 key 冷却 1h 以影响下一轮；不新增对 5xx/408 的重试。守护用例：`responses_websocket_rejection_failover_test.go`。
   - 分类冷却（`failure_cooldown.go`）：所有目标失败经 `markTargetFailure` 按类别取冷却（`failureClass`/`failureCooldownExact`，`server.failure_cooldown_seconds` 可按 401/402/403/408/429/500/502/503/504/529/5xx/network 覆盖，仅 `NewService` 读取，需重启）。账户拒绝须由调用方证明（`accountProven`：收敛透传的 `accountLevelFailure`，此时冷却已在收敛点按确认度施加，这里只计数）才走 `applyAccountRejection`，否则通用路径上的 401/402/403（如池化 WS 终态错误）按普通熔断；传输错误按 `network` 类（status 0），不按合成的 502/504。非账户类默认随 `quietPeriod` 缩放（429/500/529 为一半，其余为全额），`Retry-After` 精确使用、不翻倍、上限 10 分钟；冷却期内迟到的失败只计 `totalFailure`，不递增连续次数、不延长（`markFailureClassified`）。冷却期内迟到的固定冷却（`applyFixedCooldownLocked`）同样只计数。上游给出 5xx/429 等应答会清零发送后超时计数。`ClearMute` 同时清零未确认拒绝与超时计数，并恢复该目标 `forbidden`/`forbidden_unverified`/`unauthorized`/`invalid_token`/`billing_error`/`account_disabled` 的 key。守护用例：`failure_cooldown_test.go`、`failover_review_test.go`。
   - 429 按（目标，上游模型）冷却（`targetHealthState.modelLimits`，`markModelLimited`/`setModelCooldown`/`modelLimitedUntil`/`requestModelLimit`/`admitModel`/`modelView`/`clearModelLimit`/`modelCooldowns`）：`markTargetFailure(..., upstreamModel)` 在类别为 `429` 且模型非空时只冷却该模型，目标 `phase` 保持 `ready`、`consecutiveFailure` 不动（目标未处于冷却时，被 429 证明可达，半开探针抽到 429 即恢复目标；运行中的目标级冷却仍只由自己的探针结束）。**键**为该目标转发的上游模型原始拼写（`resolveUpstreamModel`/`ensureModelAllowed` 的结果）：同一上游的多个别名共享冷却；目标无 `model_mappings` 时键是小写的请求模型名（请求名大小写不同仍是同一键）；不同目标按各自状态隔离，同名上游互不影响。`Retry-After` 精确使用不翻倍，否则按该模型连续 429 次数以 429 类基数翻倍，封顶 8 倍；冷却期内迟到失败只计数。账户拒绝、网络、5xx、408、504 仍为目标级；每目标至多 32 个模型冷却，溢出的 429 退回目标级冷却。所有 `markTargetFailure` 调用点传入本次尝试的上游模型，传输/超时/`handleForwardError` 传空。只有同一模型的真实成功（`writeResponse` 成功分支）清该模型条目：其他模型的成功、请求类 4xx（`markReachable`）、`MarkSuccess` 都不清；`ClearMute` 清空；身份分叉的新健康对象从空开始。
     - **模型半开门**：冷却结束但条目仍在（streak>0）时，`admitModel` 只放一个请求充当该模型的探针（`modelProbe` 租约，`breakerProbeLease` 超时，随请求持有，`releaseSelected` 释放），其余请求视为“探针在途”（`blockage.busyState`、`selectionError.ProbeInFlight`）；结算：成功清条目，429 再次冷却（streak 递增），其他任何上游应答（4xx/5xx，`service.go` 在应答到达时清条目，与目标级 `markReachable` 的“可达”语义一致）也结束条目，取消则释放租约。三处准入点（粘连命中、`findAvailableRankedDetail`、显式目标）都先过该门、先于目标级准入，且租约当场消化（持有者即本次选择结果，不被排序挤掉）；准入失败（满载、目标冷却）立即归还。
     - **多 key 目标按（key，上游模型）**：通用 429（非 GLM 选择、模型非空）只记 `keyRuntime.modelLimits`（5s 起每连续一次翻倍、封顶 60s，每 key 至多 32 项，溢出回退 key 级限流），key 本身保持可用，`selectKeyForClientModel`/`selectNextActiveKeyModel`/`selectKeyModel` 按本请求上游模型跳过被限流的 key；账户类（401/402/403、额度耗尽）与 GLM 选择目标的所有 429（含读不到体的非 identity 编码）仍是 key 级（`exhausted`，`markRateLimitedFor` 的 `glmPatch` 取自 `usesGLMErrorPatch`）。同 key 有限重试（每 key 每请求一次、全局四次）不扩大，同 key 重试时 `clearKeyModelLimit(keepCount)` 解除该对限流但保留退避计数；该模型的成功清该对（`markKeySuccessModel`）。所有未被封的 key 对该模型都被限流时，`forwardRequest` 先走原有 `tryWakeUp`（尚有可唤醒的 exhausted key 时），仍无 key 可用且存在被模型限流的 key 时才不当作耗尽，返回带 `modelLimitedUntil` 的 `skipMute` 错误，`service.go` 据此 `setModelCooldown`（到最早 key 恢复，不计失败，不重置连续失败/发送后超时计数，也不恢复半开中的目标——此时上游并没有应答），之后与单 key 目标同一路径（模型级冷却 / hold / 等待）；该次 429 已作答，目标在 `attempted` 中不重发，且不再用 `lastForwardStatus=429` 抑制粘连 hold 与等待。模型限流导致的溢出选 key 只服务本次请求，不创建也不移动客户端的 key 亲和绑定（`selectKeyForClientModel`）。`KeyStatus.ModelLimits`（JSON `model_limits`）供管理端展示。守护用例：`model_cooldown_test.go`、`model_cooldown_service_test.go`、`model_cooldown_cost_test.go`、`model_key_test.go`、`keypool_model_test.go`、`model_probe_test.go`、e2e `TestModelRateLimitKeepsOtherModelSessionOnTargetE2E`、`TestMultiKeyModelRateLimitE2E`。
   - 代理内有界等待（`inproxy_wait.go`）：选路失败（`selectTargetTraced` 返回 `selectionError`）、尚未向客户端写出任何字节、非显式目标、非 MiniMax 终态时，满足全部条件才在本请求内等待**一次**：(1) 请求被粘连目标持有且该目标可等（冷却/探针在途，未对本请求发送过），或阻塞全部短暂（`selectionError.Transient`：模型级 429 冷却、非账户拒绝的目标级冷却，且最早恢复时间已知）且无缓存 4xx、本请求未收到 429；(2) 最早恢复时间距今 ≤ `inProxyWaitMax`（30 秒）；(3) 全局等待名额未满（`inProxyWaitSlots`=64，原子计数，超出计 `in_proxy_wait_rejected_total` 且不等）。满载不等待。等待恢复时间 + 0-500 ms 抖动，只受父上下文约束（不计入 `request_timeout`；父 deadline 到期按 504、取消按 499 结算，不发上游）；选路失败分支在 `releaseSelected` 之后，等待期间不持有并发槽、key、探针租约（目标级与模型级）、准入令牌。唤醒后 `attempt--` 并重新选路：粘连持有的请求先单独对未尝试过的粘连目标准入（`selectionTrace.retrySticky`），恢复了就回到它。**每请求每目标至多发送一次**：已在 `attempted` 中的粘连目标（发送前失败、已作答）既不等待也不重发，直接终态仲裁；选路失败时凡探针在途（目标级或模型级），无论之前等没等过，都允许一次最长 `inProxyProbeWaitMax`（3 秒）、每 `inProxyProbePollStep`（200 ms）重选一次的短轮询；没等过的请求把这次轮询算作它唯一的那次等待（计入 `in_proxy_wait_total`），超时按终态处理。原先立即 503 的请求最多延迟约 30.5 秒（另加探针轮询至多 3 秒）。守护用例：`inproxy_wait_test.go`、`model_probe_test.go`、e2e `TestStickyRequestWaitsForTargetRecoveryE2E`。
   - 粘连终态仲裁（`stickyVerdictPending`、`writeStickyRetry`）：只读判定（不抢探针、不改状态）：本请求首轮选路命中粘连（`selectionTrace.bound`，会话或 IP），粘连目标仍是合法候选（`stickyCandidate`：存在、未暂停、ACL、模型、路径），本请求内**所有**绑定目标都未返回 4xx（`stickyAnswered`，429 亦然；任一绑定目标已作答即不再持有，由它的应答作结论），粘连目标不处于账户拒绝冷却；此时它暂时不可用（本请求模型的 429 冷却、目标级冷却、半开探针在途、满载或 IP 软上限）或已在本请求发送前失败（`attempted`）。已知恢复时间超出绑定允许的上限则不持有、按旧逻辑回放替代目标的 4xx：会话绑定 `retryAfterMax`（10 分钟），IP 亲和 `ipStickyHoldMax`（120 秒）。持有成立时终态一律返回 503 + `Retry-After`（向上取整、≥1；满载与探针在途为 1）+ 代理生成的 `upstream_temporarily_unavailable` 错误体（`Retry-After` 取粘连目标恢复时间与其余候选最早恢复时间中较早者），优先于 429/`upstream_rejected`/裸 503 分支（MiniMax 终态与显式目标除外）：有缓存的替代 4xx 时带 `X-Upstream-Status`（替代目标状态）与 `error.substitute_error_code`（替代目标 `error.code`，缺省取 `type`，受控且至多 64 字符），没有缓存错误时两者省略；不回放上游正文、不写任何目标的 `X-Proxy-Target`；计 `sticky_retry_hinted_total`，有缓存错误时另计 `dequeue_exhausted_total`，不计 `cached_error_replayed_total`；原生 WS 事件带 `retry_after`。粘连目标自己的 4xx 出队时整体替换 `cachedFailoverError` 并重记 trace。普通“全部冷却/满载/恢复中”的 503（`writeServiceUnavailable`）补 `Retry-After`。必须保持原样：无粘连请求的首个真实 4xx、确定性错误白名单、审核类 403、客户端凭据的 401/403、显式目标、5xx/408、发送后超时、已提交响应、本地 quota/参数/415/499、粘连目标处于账户拒绝冷却时的回放。守护用例：`sticky_retry_test.go`、`sticky_verdict_test.go`、`sticky_websocket_test.go`、e2e `TestStickyRequestGetsRetryHintThenReturnsToTargetE2E`、`TestStickyRequestOnFullTargetGetsRetryHintE2E`、`TestUnboundRequestStillGetsFirstRealErrorE2E`。

   - 粘连写入（`binding_write.go` 的 `writeBindings`，由 `ServeHTTP` 经 `writeResponse` 的 `beforeCommit` 回调触发）：2xx 响应头提交、首字节写出之前预写 IP/会话绑定（`affinityMap.Prewrite` 在同一把锁内记录原条目并写入，得到 `affinityUndo`），保证每请求新开连接、零间隔发下一个请求的客户端能命中（Issue #202）；WS（含原生 WS 轮次与上游 WS 适配）、透传非 2xx、账户级失败不预写，仍在 `writeResponse` 返回且 `delivered` 后写入（`writeDeliveredBindings`：同一 `writeBindings` 规则，写后立即 `Confirm`，不留待结算节点，避免长 WS 会话逐轮串成无限链；`TestDeliveredBindingsAreNotLeftPending`）。`writeResponse` 返回后由 `settlePrewrittenBindings` 结算：每次预写在条目上挂 `affinityProv` 节点（`prev` 指向它所覆盖的预写，重叠请求形成链）。`delivered` 则 `Confirm`：节点转正为普通绑定，仍有效的滑动绑定刷新到完成时刻（`Confirm` 不续期临时绑定）；若响应时长超过滑动 TTL 使绑定已过期，按旧行为在完成时刻重建（`Revive`，只在该 key 无有效绑定时写，不覆盖已被并发替换为其他目标的绑定；临时绑定 `rebuildNever` 保持绝对过期、不复活；首选层写入的 `rebuildAlways`；命中类 `rebuildIfPreferred` 仅当目标仍在首选层才重建）。否则逆序 `Rollback`：仅当该 key 当前仍挂着本请求的节点才动，并沿 `prev` 链恢复到最近一个未失败的状态（已确认的、仍在途的重叠请求的预写、链起点处的普通旧绑定），都没有则删除——不会把另一个同样失败的预写复活；被并发请求改写（新条目无该节点）的不回滚。命中已有绑定的 `Touch` 同样走预写与回滚；非首选层的预写仍是临时绑定。绑定只为完整送达的响应保留（`writeResponse` 的 `delivered`，由 `responseDeliveredInFull` 判定：上游 2xx、生命周期未失败、响应体完整写到下游且无写错误）；响应写完后客户端立刻断开（前置 nginx 无 upstream keepalive，每个响应后都会关连接）使请求 ctx 被取消，请求统计可判为 Canceled，但送达已完整，仍写绑定、仍计 `in_proxy_wait_success_total`；中途断开、copy 出错、流不完整（无终止事件）、`lifecycleFailed` 仍不写。copy 里出现的 `context.Canceled` 只有在已拷贝声明长度或已见流终止事件时才算完整。`requeststats` 的统计口径不变。守护用例：`binding_disconnect_test.go`、`binding_settle_test.go`（重叠失败预写不复活、长响应后重建滑动绑定）、`binding_prewrite_test.go`（零间隔短连接、头提交前已有绑定、未完整送达回滚、并发改写不被覆盖、临时绑定、非 2xx 不绑定）、e2e `TestBindingSurvivesConnectionCloseE2E`、`TestBindingZeroGapShortConnectionsE2E`；首轮选路命中或 failover 粘连（`affinityBound`）后同一请求的后续尝试即使被报告为轮询也不写 IP 粘连；持有半开探针租约的请求不新建绑定（可刷新自身已有绑定）。守护用例：`TestIPAffinityNotHijackedAfterForwardFailover`、`TestAffinityNotWrittenOnFailedResponse`。

   - WS 生成传输失败的集中诊断日志区分内部原因状态（取消 499、超时 504、其余 502）与客户端拟返回状态，两者职责不同。原生 WS 发送失败保留错误事件中的 502，不表示升级后另发 HTTP 502；客户端断开时拟返回状态不证明已送达。日志记录失败阶段、可能已发送与 `replayed=false`，不记录凭据、请求体或上游错误正文。
   - 可重试网络错误（连接拒绝、DNS 等，`classifyTransportError` 为 502）可切下一 target；`context.DeadlineExceeded`、请求可能已发出后的网络层超时（504，如等待响应头超时）与 `context.Canceled`（499）均不可重试，防止重复推理或扣费。唯一例外：可证明发生在发送任何请求字节之前的超时（拨号阶段 `net.OpError`、TLS 握手超时，见 `isPreSendTransportError`）按网络错误 failover 并降级该 target。拨号超时必须为 8s；真实拨号超时同时匹配 `context.DeadlineExceeded`，故 `isPreSendTransportError` 须在 attempt 与父上下文均有效时先识别 dial `OpError`，并在错误分支 `cancel()` 之前判定；父取消/deadline 或 attempt 超时仍为 499/504、不 failover。同类例外：上游 WebSocket 升级握手在收到任何升级响应前超时（`errResponsesWSHandshakeTimeout`），且 attempt 与父上下文仍有效时，属于发送前（未发送 `response.create`）→ 可 failover 一次并 `MarkFailure`；绝不在同一 target 回退 HTTP；单 target 的池化 HTTP 请求与 HTTP 拨号超时一样以 503 结束。保留 `TestServiceTimeoutDoesNotRetryOrMute`、`TestCoreReviewNetworkTimeoutRetriesOnlyBeforeSend`。该红线约束的是“没有终态响应”的超时与取消；上游已返回 4xx/5xx 终态状态码（如 429、402）后，按既有规则做的有限同 key 重试或换 key 不属于超时重试，即使读取错误体前缀时上下文到期也一样：按既有拒绝响应契约处理，不扩大允许重试的状态及分类范围。
   - 上述拒绝响应例外仅在父请求 `r.Context()` 仍有效时成立。父请求取消或 deadline 后停止同 key 退避、换 key、全池耗尽补发及 failover；HTTP 429 与 GLM 瞬时 SSE 的 1 秒退避可中途取消，不为未执行的重试解除 exhausted。父取消沿用 499/canceled，父 deadline 沿用 504/failure，不因父上下文结束 mute target。429/402 状态本身不能绝对证明上游未推理或未扣费。
   - 客户端断开时的用量结算（底层规则，与协议/传输无关）：中断就是中断，客户端取消照常立即取消上游，不排空、不重试、不重放。上游请求可能已发出（已发送请求字节或 WS 已发 `response.create`）而尚未取得该协议官方最终用量字段时，记 0 token、`incomplete`、`cost_incomplete` 的用量事件，诊断 `client_disconnected_no_usage`，部分观察值清零；写 Warn 日志（不含正文/凭据）并累计 `usage_client_gone_no_usage`。断开前已取得最终用量的按官方字段完整记账。可证明未发送字节的取消不写事件。非客户端原因（上游出错/断流、超时、观察或解码失败、缺终态或缺官方最终用量、Claude 重叠守卫终止、WS 终态失败）同样清零，诊断 `upstream_interrupted_no_usage`，日志带 `cause`，计数 `usage_upstream_interrupted_no_usage`；原有具体诊断保留并追加。官方最终用量：Responses/Anthropic 为 finalUsage；Gemini 为带 usageMetadata 的块到达时所有已见 candidate 都有 finishReason；Chat 等 SSE 为 `[DONE]`，或带 usage 的块到达时所有已见 choice（按 index 跟踪）都有 finish_reason（含 choices 为空的末尾 usage 块）；非流式为完整 body 的 usage。完整返回但无 usage（`missing_usage`）、已取得最终用量但数值冲突、非 2xx 拒绝维持原状。“可能已发出”以 HTTP `GotConn` 或 WS 已发 create 为界。一个客户端请求至多一个用量 bundle，由持久化层原子展开为 root 与关联附属记录，仅 root 计入请求数：响应头前已发出但随后重试/failover 的尝试只写 Warn（`will_retry=true`）并计数，由最终结果结算；最终响应不被观察（`responseObservesUsage` 为假：非 2xx 且非 WS 已发 generation）时，之前已发出且无官方用量的尝试仍记一条 0 token 不完整事件（`upstream_interrupted_no_usage`），最终非 2xx 本身不计费，没有已发出尝试时不记。待结算事件的 model 用请求循环传入的 upstreamModel（与正常事件同一口径，不带 ModelPrefix）。各路径共用 `settleNoOfficialUsage`。WS 收到终态帧（failed/incomplete/error）但无 usage 时与 HTTP 一致，按完整无 usage 处理。已取得官方最终用量后才发生的断开或中断记官方值（不降级），追加 `client_disconnected_after_final_usage` / `interrupted_after_final_usage`；观察失败、解码校验错误与 Claude 重叠守卫不属此类。待结算 0 事件使用已发送那次尝试自身的 path 与协议。两条 Warn 日志为中英双语，按 msg 检索的告警需同步。
   - 父上下文结束时，已有成功响应或已发送生成的 WS 响应仍走既有用量结算，不完整时也须记录事件；禁止的是后续重试，不能丢弃已知用量。WS 本地响应仍走既有完成路径，不为未发送的生成新增用量事件。退避期间 key 保持 exhausted，因此同目标其他请求可能选择其他 key 或走既有耗尽处理；这是不为未执行重试 unmark 的结果，不另改并发策略。
   - 已提交的官方最终用量快照具有粘性：尾部非终态帧、空 `message_delta` 或仅重复输出的帧不得覆盖或重算 token、模型、组件及计价上下文；只有新的合法最终快照可整体替换。尾部或终态后的失败与诊断仍保留（如 `interrupted_after_final_usage`），不得被后续 `message_stop` 清除。
   - Anthropic 替换候选还须验证 iteration 归属、计数及求和，包括仅含 `message` 的数组。已见非空 iterations 后，缺失、null 或非数组的候选不能替换已提交快照，也不能污染后续 final 的 model、缓存、TTL 或计价上下文。首个 final 的保守处理不变；未见 iterations 的普通 final、显式 `[]` 及合法但费用不完整的快照仍按原语义处理。error 后的 `interrupted_after_final_usage` 独立于记账证据，跨合法替换保留；干净替换不生成该标记。
   - 非 2xx 的 4 KiB 错误体前缀读取失败记录 `partial_error_body`，仅含 request_id、target、status、bytes_read 与受控 error_category；不记录正文、原始 error 字符串、凭据或 URL。正常 EOF 与无错误的长度限界不记录该诊断；日志不改变前缀回放、原有拒绝分类或有限重试策略。真实 HTTP 回归见 `non2xx_context_test.go`。
   - 切 key 或 target 时须释放旧请求的响应体、上下文与并发占用；每次选中的 target 都须通过其准入检查。
   - 改动前先跑 `go test ./internal/proxy/ -run 'Retry|Timeout|Failover|GLM|Admission' -v -count=1`；改动后完成本目录全量回归。
2. **路径感知路由**：目标选择顺序是「model 过滤 → 请求 schema 过滤」；调整 `internal/config/endpoint_type.go` 的 `RequestSchemas` 能力声明或 `path_capability.go` 的请求 schema 分类，会直接改变线上路由结果，必须补对应测试。
3. **连接粘连降级**：粘连目标不可用或路径不兼容时必须降级为轮询，不能让请求失败。所有策略（含成本优先与性能优先）都不主动打断客户端粘连：粘连目标（IP 亲和或会话绑定）只要能承接新请求（存在、未暂停、未冷却、路径兼容、有容量）就继续命中，即使存在更便宜的层；仅在粘连目标无法承接时临时改选（`selectionFailover`，成本池按成本分层+负载选择），不迁移也不覆盖原绑定（IP 亲和在 failover 时不更新，会话绑定只随永久配置变更而变），粘连目标恢复后自动回到它。已删除 `selectionCostRebind` 让出路径。
   - 粘连与模型级冷却、有界等待：粘连命中前先检查目标对本请求上游模型的 429 冷却（同一目标的其他模型照常命中）；粘连目标暂时不可用时，请求先在替代目标上尝试，替代目标的 4xx 不是粘连目标的结论——能等则在代理内有界等待（红线 1），等不到则 503 + `Retry-After` 提示重试，粘连绑定始终不迁移、不覆盖（`selectionFailover` 不写 IP 亲和，会话绑定只随永久配置变更而变），恢复后自动回到原目标。
   - 成本池无粘连例外：成本分层只决定没有粘连的请求或粘连目标无法承接时的选择，粘连目标即使处于更贵的层也继续命中。成本比较以客户端别名为单位，有 `model_mappings` 的成员须能经自身映射解析该请求名（paused 映射除外）；无 `model_mappings` 的成员接受任意请求名，按请求名本身解析/取价。上游名请求不反查别名，不以别名声明价回退。IP 亲和 Set 侧写实际服务成员的上游原始拼写，Get 侧依次尝试该请求名在各成员映射出的上游拼写。守卫用例：`TestCostRoutingAffinityDoesNotYieldToCheaperTier`、`TestCostRoutingNextRequestKeepsSessionBinding`、`TestCostRoutingEmptyStrategyDefaultsToCost`、`TestCostRoutingAliasStickyTargetIsNotYielded`、`TestCostRoutingComparesMembersByClientAlias`、`TestCostRoutingUpstreamRequestStaysWithinDeclaringMembers`、`TestCostRoutingMemberWithoutAliasDoesNotJoinComparison`、`TestCostRoutingPausedAliasMappingDoesNotCompete`、`TestCostRoutingDoesNotUseAliasPriceFallback`、`TestCostRoutingSharedUpstreamAndAliasNameComparesDeclaringMembers`、`TestCostRoutingDebugLogsAliasFirstCandidates`、`TestIPAffinityAliasWithDivergentUpstreamSpellings`、`TestIPAffinityTriesLaterSpellingWhenFirstBindingUnavailable` 及 e2e `TestPoolCostRoutingComparesByClientAliasE2E`、`TestPoolCostRoutingFollowsPricesE2E`、`TestPoolEmptyStrategyRoutesByCostE2E`、`TestPoolLoadRoutingIgnoresPricesE2E`；`TestCostRoutingNeverReducesAvailability` 守卫“价格不得降低可用性”（价格只收窄已准入候选，不得移除最后一个可用项）。
4. **净化仅限 Azure**：`sanitize.go` 的字段白名单只对 `azure_openai` 生效；给其他 endpoint_type 加请求体改写要走 `provider_profile.go` / `custom_inject.go`，不要扩散白名单逻辑。
5. **配置热更新与目标熔断**：同名目标的上游连接身份变化，或生效后的 `Paused` 从 true 变 false（含池恢复），须分叉新的 `targetHealthState`，清除冷却、连续失败和探针租约，保留分叉时的累计计数及成功/失败观测时间。身份字段为 `endpoint_type`、`endpoint`、`auth_mode`、`allow_bearer_passthrough`、合并去重后的凭据集合、`custom_headers`、`custom_body`、`model_prefix`、`openai_prefix`、`anthropic_prefix`、`prefer_websocket`；仅重排凭据不重置，路径前缀按现有归一化结果比较。`usage_adapter`、`model_mappings`、`max_concurrency`、`pool`、`key_reset_time` 等非身份编辑、暂停及编辑其他目标继续共享原熔断状态；池恢复但目标仍暂停时不重置。旧代际在途结果只结算其原 health 对象，不得重新静默新身份或释放新身份探针；同身份代际仍须保留迟到结果及 successor 探针保护。keyPool、并发占用、runtimeWindow 与 AIMD 沿用原共享规则，不新增重试。新增 `Target` 导出字段须在 `TestHealthIdentityFieldClassificationExhaustive` 分类，并验证对应的重置或保留边界。

## 计费类型与厂商特殊处理

- 持久化目标的 `usage_adapter` 必须显式选择 `standard`（原厂规则）、`qwen`、`glm`、`deepseek`、`kimi`、`openrouter` 或 `minimax`，共七项，新建无默认值。它是用量/缓存、厂商错误、限流与额度处理的唯一选择依据；运行时不根据 host 或模型白名单推断，不接受 `auto`。`endpoint_type` 仍只决定认证、路径和协议能力。
- `standard` 按实际请求协议使用 OpenAI、Anthropic 或 Gemini 原厂用量解析器，即使目标使用厂商官方域名也不启用厂商 Patch。显式厂商选择适用于该目标的所有模型及转发网关。Gemini 用量始终保持原生解析，但厂商错误策略仍按显式选择执行。
- Anthropic 原厂规则（`usage_protocol_claude.go`，适用于 `standard` 及所有走 Claude 解析的目标，不按 host/模型名推断）：
  - 单个快照中 `usage.iterations` 缺失、非数组或为空时不追加 iteration 费用；SSE 的早期与终态证据还须按下述规则核对。合法 `message` 的计数和须与顶层一致，executor 用量继续只取顶层；缓存字段可省略，部分已知和只作下界，超过已报告顶层为 `iterations_usage_mismatch`，顶层缺该缓存而已知和大于 0 为 `unknown_usage_iterations`，不把缺省缓存推为 0。归属及重叠可证明时，`advisor_message` 按其显式 model、`compaction` 按其 model（缺省取实际 upstream）生成独立组件；按需压缩的顶层全 0。
  - fallback 链中较早的 `message` 可有各自 model，最后 `fallback_message` 与顶层重叠，root 按最后模型计价，不再重复保存最后一项；此前有输出的 attempt 独立收费，无输出且无该 attempt 分类时保留 NonBillable 组件并标 `unknown_fallback_refusal_billing`。
  - 所有 Anthropic root（普通、带 message/advisor/compaction 或 fallback）均适用零输出 refusal 规则：必须实际观察到有效 `output_tokens: 0`、无计数冲突且 `stop_reason` 为 `refusal`；缺失、null 或非法输出不能当成已知 0。只读结构化 `stop_details.category`，不解析 explanation。`bio` / `frontier_llm` / `reasoning_extraction` 收费；`cyber` / `general_harms` / 明确 null 免费；未知字符串、缺失或非法 category 暂不收费并标费用不完整，保留已有诊断，否则普通 root 为 `unknown_refusal_billing`、已归属 fallback root 为 `unknown_fallback_refusal_billing`。官方规则将其他 category 也列为免费，未知值暂缓并诊断是项目的保守策略，不是官方限制。root 免费不免除独立组件费用。
  - 组件只用自身计数及用量中的 tier/speed 定价，不能借用 executor 的请求或阈值；缓存缺值保留未观察。任何归属、计数、溢出或求和不能证明的形态不追加费用，缺 `type` 仍保守处理；保留 multi_model > compaction > unknown > mismatch 诊断优先级，`server_tool_charges` 仍可覆盖；顶层计数及 usage_status 不由这些诊断改写。
  - SSE 仅使用带 `stop_reason` 的最终 `message_delta`，或经 `message_stop` 确认的最后 delta 的完整 iterations 快照；中间 delta 不作为最终用量。早期见过非空 iterations 而终态快照缺失该数组（含 null）时标 `missing_final_iterations`，不沿用早期组件。fallback 的最终 usage 整体替换 executor 的早期快照，不能继承输入、缓存、TTL、thinking 或 tier/speed。缺 input 时标 `missing_fallback_input_usage`；归属可证的已知 output 只按返回的 fallback 模型计价，仍不完整，不补输入或组件。未取得官方最终用量的清零同时清除组件。已确认终态后收到 Anthropic `error` 时保留已知用量、模型、组件及计价上下文，记录失败并追加 `interrupted_after_final_usage`；只有未确认的中间用量仍清零，后续 `message_stop` 不得恢复它或覆盖失败状态。解码损坏与 Claude 重叠守卫仍沿用既有处理规则。
  - 目标 `ModelPrefix` 只加在出站顶层模型上，`tools[].model`、`fallbacks[].model` 等显式附属模型按客户端原文出站。解析器从目标取得前缀，对上游回显的迭代项 `model`、`fallback_message.model` 及作为 executor 兜底的响应信封 `model`，先按原拼写比较，不相等时才按去前缀后的拼写比较；去前缀仅在完整前缀匹配（大小写不敏感）且余下非空时进行，其他拼写差异（快照 ID、别名）不推断。executor 比对用请求侧上游模型（本身不含前缀），message 项原拼写或去前缀拼写任一相等即可，迭代项之间的同模型判断同理；未配置前缀的目标行为不变，两种拼写都不匹配仍判 invalid/不完整。组件与 fallback root 的显式回显模型与请求准入集合（executor 上游模型及最终出站体的 advisor `model`、`fallbacks[].model`、`fallback_model`）大小写不敏感比对，同样先原拼写、后去前缀拼写；命中则按准入侧拼写（小写，与现有用量口径一致）落账，额度归组与准入检查一致（客户端自带前缀或名字恰以前缀开头时按原拼写命中，不被削去）。两次都未命中时按去前缀后的回显拼写落账，并写 Warn「回显附属模型不在准入集合内 / echoed supplementary model not in admission set」（字段 request_id、target、iteration_type、model，不含正文或密钥）；同一请求按 (iteration_type, model) 去重、最多 3 条，model 按 UTF-8 边界截断到 128 字节，超出部分只计数并汇总为一条「回显附属模型超出单请求日志上限，已汇总 / echoed supplementary models over per-request log limit; summarized」（字段 logged、dropped）。fakellm `iteration_model_prefix` 为非官方合成假设：所有回显模型挂在该命名空间下（已带前缀者不重复），executor 与 compaction 项回显收到的请求模型。
  - 一次请求只写一个含组件的 bundle，由持久化层原子展开；附属记录不重复增加请求数；keyPool 的 token 负载按 root 与组件实际工作量合计一次（免费 attempt 仍计，reasoning/TTL 子集不另加，单次合计饱和防溢出）。

- 上游 WS 池：`/admin/metrics` 的 `responses_ws` 提供命中/握手/回退/预热计数与 dns/tcp/tls/upgrade 握手分段直方图，相邻握手变化头只记头名。新鲜备用 lane 预热（按 provider 认证头精确匹配凭据退役，迟到的不可用回调先复查 key 状态）：每客户端至多 1 条、只用身份头、`responseID` 为空；新请求等待在途备用拨号至多 200ms 后自行拨号，备用拨号结果不得让前台失败或变慢；keypool 判耗尽/屏蔽时取消在途备用并退役空闲备用；配置发布（`replaceTargetsLocked` → `invalidateForConfig`）递增代次、清除 unsupported 与预热退避记忆（保存后重新探测）、取消在途备用并退役未持有 `responseID` 的空闲 lane；lane 须记录创建时的目标名，目标已被删除、或握手凭据不在该目标新 key 集合中的 lane（无论是否持有 `responseID`）一并退役，空闲者立即在锁外关闭，忙碌者释放时关闭，不得留到空闲回收；其余持有 `responseID` 的空闲 lane 与忙碌 lane 保留（lane key 已绑定 URL 与认证头，身份变化无法命中），无关保存不打断池化续接；lane 记录创建时的池代次，旧代次 lane 释放时不预留备用、不发起新握手（其凭据可能已被保存删除），未持有 `responseID` 者释放即退役，持有者继续服务续接；手动 BlockKey（`retireLanesForCredentials`）退役该凭据的全部 lane（含持有 `responseID` 者，忙碌者释放时关闭），其他凭据不受影响；熔断分叉日志在配置写锁释放后输出；名额让出顺序为空闲备用→在途备用→最久未用 lane；`prewarm_handshake_*` 与前台 `handshake_*` 直方图分开；后台拨号的任何结果不得进入 keypool、熔断或 unsupported 记忆，失败按 key 退避 1 分钟；续接请求绝不使用备用 lane。池内连接在锁外关闭。原生会话在无进行中 turn 且上游空闲 30s 时 ping 上游，失败关闭连接，下一轮按既有规则（新连接或 409）。下游侧：pong 与任意客户端帧刷新存活时间；仅在有进行中的轮次时（轮次开始即重置存活时间），超过 max(4×ping 间隔, 2 分钟) 未收到才判半开，经 `WriteControl` 发 1001 关闭帧（"client unresponsive"）后取消会话并释放名额；两轮之间不做此检查（gorilla、coder/websocket、tungstenite 等只在应用读取时应答 ping），只受 15 分钟空闲计时约束，不设固定读超时；仅空闲（1000）与排空（1001）关闭在写关闭帧后最多等待 1s 对端关闭或 ctx 结束，其他强制关闭路径不变。上游关闭帧（`websocket.CloseError`，不含代理自身 CloseNow）在池化路径也以 `%w` 包装 `io.ErrUnexpectedEOF`，关闭码进入诊断日志字段 `upstream_close_code`，上游 1008/1009 不豁免熔断。
- 观察解码预算：br 与 zstd 共用全局预算（默认 512 MiB，环境变量 `LLMS_OBSERVATION_DECODE_BUDGET_MB`）。br 开流即按窗口预留 1.2×((1<<WBITS)+256 KiB)（解码器可能在首个 metablock 头就分配整个窗口，逐步预留会滞后），large-window 拒绝，512 MiB 下 lgwin 22 约 100 路、lgwin 24 约 26 路；zstd 单段帧 >8 MiB 按 FCS 预留，不足回落 8 MiB 上限。预留失败按观察失败记 0（cause=observation_failed），转发字节不变；`usageObservationEnabled()` 为真时 `forwardRequest` 从上游 Accept-Encoding 去掉 br（保留其他编码与 q 值，含 `*` 时追加 `br;q=0`，变空设为 `identity` 而非删头——删头会触发 `doHTTP` 透明 gzip 改变透传字节），防客户端借预算耗尽规避计费；`/admin/metrics` 的 `observation_budget` 提供容量、占用与按编码的耗尽计数，耗尽告警每 10s 至多一条。
- 落库：用量先同步追加并 fsync 恢复日志，再由后台批量提交 bbolt（`RecordBatch` 按 RecordID 幂等），额度内存计数仍在 handler 返回前同步更新；请求完成统计入有界队列异步写，满则丢弃并计入 `record_failures`；`MaxBatchDelay=2ms`。额度校准（DrainClient）等待该客户端排队事件由写入器批量提交（最多 10s，超时本轮校准放弃、保留现有计数、该客户端准入按校准失败语义暂时拦截并退避重试，不丢账不重复），仅写入失败或遗留（foreign）事件逐条重放；无 foreign 行时回放与校准不读整个 journal。`cmd/proxy` 以 `os.Exit(run())` 退出，所有 defer 在出错路径同样执行。关停顺序（正常与启动出错路径一致）：停止接收并等待 handler → 排空 WS → `proxyService.Close` → 排空用量与统计队列（总超时 30s，超时记 Error，剩余用量留在 journal 待下次 Replay）→ Replay → 关闭 bbolt。统计写失败日志每 10s 至多一条并带 `dropped`；`/admin/metrics` 的 `persistence` 提供 `usage_async_pending`、`usage_async_deferred`、`request_stats_dropped`。
- 请求完成统计由 `SetRequestStatsRecorder` 独立注入：Service 调用（原生 WS 按有效 create 轮次）结束后只记一次，重试不另计；不含 Service 前鉴权/IP 拒绝、健康/管理/ping、升级/会话控制及无效或鉴权复核拒绝消息。保留原有指标、健康和用量结算，统计写失败不得改变响应或额度。SSE 完整终态与 usage 是否存在分别判断；终态缺失为失败，有终态无 usage 可成功。总览查询仅覆盖最近 72 小时已结束分钟，详见 README 的请求完成统计口径。
